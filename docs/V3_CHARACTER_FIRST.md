# H3 Studio — キャラ起点の作り直し（2026-09-29〜）

## 方針（オーナー決定 2026-09-29）

- アプリの軸は3つ。**トレース**（6〜12秒を1本）、**量産**（動き1つ × キャラ画像を複数）、**1分**。
  それ以外（Image Trace / Prompt Cinema / 解像度・Turbo の A/B / final_hq）は計画から外す。
  画面から外すだけで、baseline のワークフローとノードはそのまま残す。
- **どのモードも「キャラ」から始める。** キャラと、それを描く LoRA は C_STUDIO にある。
- **H3 は C_STUDIO の LoRA を読み込めない。** C_STUDIO の LoRA は画像モデル（SDXL / Qwen）用で、
  H3 は別の動画モデル。二つをつなぐのは、LoRA が作った**画像**。
- **H3 は C_STUDIO の Character Pack を読むだけで、書き込まない。**
  `CHARACTERS/<id>/character.json` の `state: "accepted"` の画像だけを使う。C_STUDIO 側の決まりで、
  この形は壊さないことになっている。これが「2か月は別々に進める」（CH3 構想）の、合意済みの例外。
- **6〜12秒で成功したトレースは、自動で量産候補になる。** 作るボタンは無い。候補は「動き」（元動画）。
  同じ動画を2回アップロードしても1つにまとめる（中身のハッシュで判定）。候補から外すのは「しまう」だけで、何も消さない。

## 量産の本線の変更（オーナー判断 2026-10-05）

- Studio の画面は使わない。生成は Claude Code の会話から Studio の API を呼んで行う（`.claude/skills/h3-tsukuru/`）
- 量産の本線は **Image Trace（FL2VA）× ダンスプロンプト**になった。9-29 に計画から外した Image Trace を、画面ではなく
  会話からの量産として戻す。トレース（Motion Trace）は元動画が要り、権利と素材集めが重いため
- 実測（全身の元画像・10秒・0.4MP・12 steps）: 1本 約6〜7分。5本で Pod 約40分
- オーナーの好み: 背景が切り替わるのは嫌（部屋のまま）。歩き回らない。ダンスはよい

## 顔と服の決まり（実測 2026-09-09、再掲）

顔は、服を指定した側の体に付いてくる。キャラの顔で出したいなら、**服もキャラ画像から取る**。
キャラ画像は「着せたい服を着た姿」にする。

## 実績の数字（Motion Trace 下書き・0.4MP・12 steps・RTX 6000 Ada）

- 6秒: 平均 591秒（成功9本）
- 10秒: 平均 1806秒（成功5本）
- 12秒: 1328秒（成功1本）
- 6秒の Final: 1回試して成功0回。量産と1分は、まず下書き画質で作る。

量産の見積もり（推定）: 6秒 × 10本 ≈ 100分 ≈ $1.40。1分モード（6秒 × 10区切り）も同程度。

## 段1で入ったもの

- `studio/characters.py` — C_STUDIO の台帳を読む。書き込み用に開くコードが無いことをテストで確認している
- `studio/shelf.py` — 量産候補（6〜12秒・成功・長尺の区切りではない・元動画がこの Mac に残っている）
- API: `GET /api/characters`、`GET /api/characters/<id>`、`GET /api/characters/<id>/image/<asset>`、
  `POST /api/characters/<id>/use`（H3 の uploads に**写して**から使う）、
  `GET /api/shelf`、`POST /api/shelf/use`、`POST /api/shelf/hide`
- 画面: 「作るもの」はトレースだけ。元画像の欄にキャラと画像の一覧、元動画の欄に量産候補の一覧。
  候補を選ぶと、長さが入り、プロンプト欄が空ならそのとき成功したプロンプトも入る
- C_STUDIO の場所は `H3_CSTUDIO_CHARACTERS`（既定 `~/Downloads/C_STUDIO/CHARACTERS`）
